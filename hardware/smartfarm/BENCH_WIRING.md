# 벤치 배선 표준 (Bench Wiring Standard)

테스트 배선이 늘어나도 꼬이지 않고, 센서를 5분 안에 추가/제거할 수 있게 하는 규약이다.
**ESP32와 ESP8266을 함께 쓴다**는 전제로 설계했다.

핵심 원칙: **논리 신호 이름과 물리 핀을 분리한다.**
배선·커넥터·라벨은 신호 이름(`AIN1`, `RELAY1`, `SDA`…)으로만 만들고, 칩별 핀 번호는 3장의 매핑 표가 흡수한다.
그래서 ESP8266 노드와 ESP32 노드가 **같은 하네스에 서로 바꿔 꽂힌다.**

**핀 할당의 단일 출처(single source of truth)는 이 문서이며, `soil_node/config.h`는 이 표를 따른다.**
둘이 어긋나면 배선 사고가 난다 — 변경 시 이 문서를 먼저 고친다.

## 0. 왜 바꾸는가

현재 방식(브레드보드 + 20cm 듀폰 점퍼 + 공중 배선)의 한계는 미관이 아니다.

1. **칩마다 배선이 달라진다**: ESP8266은 아날로그가 A0 하나, ESP32는 ADC1 6채널. 금지 핀도 서로 다르다.
   신호 이름으로 규격을 고정하지 않으면 구역마다 다른 배선이 생기고, 노드를 교체할 때마다 처음부터 다시 짜야 한다.
2. **아날로그 채널 제약**: ESP8266은 A0 **하나뿐**. ESP32도 **WiFi를 켜면 ADC2 계열(GPIO 0·2·4·12~15·25~27)의 아날로그 읽기가 동작하지 않아**
   실사용 채널은 ADC1의 6개(GPIO 32·33·34·35·36·39)다. 토양수분·EC·수위·pH를 붙이면 금방 닿는다.
3. **입력 전용 핀의 floating**: ESP32 GPIO34~39는 입력 전용이고 **내부 풀업/풀다운이 없다.** 미배선 상태로 두면 노이즈를 읽고,
   그 값이 `soil`로 발행되면 허브가 진짜 건조 신호로 믿고 펌프를 켠다 (2026-07-25 zone1에서 실제 발생).
4. **접촉 불량 = 오작동**: 브레드보드 접점과 듀폰 커넥터는 반복 탈착 시 접촉 저항이 커진다. 신호선이 순간 뜨면 3번과 같은 결과가 된다.
   배선 신뢰성은 스마트팜에서 **안전장치의 일부**다.
5. **재현 불가능**: 선을 뽑았다 다시 꽂으면 이전과 같은 배선이라는 보장이 없다. 테스트 결과를 신뢰할 수 없다.

## 1. 목표 구조

```
        [12V 어댑터] ──> 단자대(12V) ──> 펌프 (+릴레이 접점)
        [5V 어댑터]  ──> 단자대(5V)  ──> 릴레이 코일, 노드 VIN
                              │
                          GND 단자대 (단일 합류점 / star ground)
                              │
   [노드 캐리어] ── I2C 2선 ──> [I2C 허브] ──┬── BME280 (온습도)
    ESP32 또는 ESP8266                       ├── BH1750 (조도)
        │ AIN1                               └── ADS1115 (아날로그 4채널 확장)
        │ RELAY1~3
```

- **보드 위(≤30cm) 센서 확장은 I2C**, **구역 간 거리 확장은 ESP 노드 추가 + MQTT**로 나눈다.
  I2C를 멀리 끌지 않는다(총 배선 정전용량 한계, 실전 1m 이내). 구역 확장은 기존 README 5번 절차 그대로다.
- **I2C 확장은 두 칩 모두에 동일하게 적용된다.** 특히 ESP8266은 A0 한 채널이 곧 한계이므로,
  아날로그 센서를 2개 이상 붙이려면 ADS1115가 사실상 유일한 답이다.
- 펌프/12V 전류는 **브레드보드를 절대 통과하지 않는다** (브레드보드 접점 정격 ~1A).
- 노드 전원과 릴레이/펌프 전원을 분리한다. 공유하면 펌프 기동 시 전압 강하로 노드가 리부팅하고,
  부팅 중 릴레이 출력이 튄다. **공통은 GND만.**

## 2. 노드 신호 규격 (칩 무관 — 하네스는 이것만 안다)

| 신호 | 방향 | 용도 | 커넥터 |
|---|---|---|---|
| `SDA` / `SCL` | 양방향 | I2C 센서 버스 | P2 |
| `AIN1` | 입력(아날로그) | 토양수분 등 1채널 | P4 |
| `RELAY1` | 출력 | 펌프 릴레이 | P3 |
| `RELAY2` | 출력 | 예비 릴레이 (밸브/조명) | P3 |
| `RELAY3` | 출력 | 예비 릴레이 — **ESP32 전용** | P3 |
| `DHT` | 양방향 | DHT22 데이터 (I2C 온습도로 교체 시 불필요) | P4 |
| `+5V` / `+3V3` / `GND` | 전원 | | P1 / P2 / P4 |

**커넥터 규격 (두 칩 동일, JST-XH)**

| 커넥터 | 핀 | 내용 |
|---|---|---|
| P1 전원 | 2 | `+5V`, `GND` |
| P2 I2C | 4 | `+3V3`, `SDA`, `SCL`, `GND` |
| P3 릴레이 신호 | 4 | `RELAY1`, `RELAY2`, `RELAY3`, `GND` (릴레이 코일 5V는 단자대에서 직접) |
| P4 센서 | 4 | `+3V3`, `AIN1`, `DHT`, `GND` |

노드마다 **만능기판 소형 캐리어**를 하나 만들어 ESP 모듈 + P1~P4 커넥터를 올린다.
ESP8266 캐리어와 ESP32 캐리어는 **핀 배치가 같아 서로 교체 가능**하다. 칩이 바뀌어도 하네스는 그대로다.

## 3. 칩별 핀 매핑

### ESP32

| 신호 | GPIO | 비고 |
|---|---|---|
| `SDA` | 21 | 표준 I2C |
| `SCL` | 22 | 표준 I2C |
| `AIN1` | 34 | ADC1. 입력 전용, 풀업/풀다운 없음 |
| `DHT` | 4 | 디지털 사용은 무방 (ADC2라 아날로그로는 못 씀) |
| `RELAY1` | 26 | 부팅 클린 |
| `RELAY2` | 25 | 부팅 클린 |
| `RELAY3` | 27 | 부팅 클린 |
| 여유 아날로그 | 32·33·35·36·39 | ADC1 |
| 여유 디지털 | 16·17·18·19·23 | 부팅 클린 |

**금지 핀**: `6~11`(내장 플래시, 절대 금지) / `0·2·12·15`(스트래핑 — 특히 **GPIO12는 부팅 시 HIGH면 부팅 실패**) /
`1·3`(시리얼) / `5·14`(부팅 시 출력이 튀므로 릴레이 IN 금지).

> 현행 ESP32 배선(34 / 4 / 26)이 이 표와 **이미 일치**한다. I2C(21/22)만 새로 얹으면 되고 재플래싱은 필요 없다.

### ESP8266 (NodeMCU)

| 신호 | 핀 | GPIO | 비고 |
|---|---|---|---|
| `SDA` | D2 | 4 | 표준 I2C |
| `SCL` | D1 | 5 | 표준 I2C |
| `AIN1` | A0 | — | **유일한 아날로그.** 2채널 이상은 ADS1115 필수 |
| `RELAY1` | D5 | 14 | 부팅 클린 |
| `RELAY2` | D6 | 12 | 부팅 클린 |
| `RELAY3` | — | — | **없음** (핀 부족). 3채널이 필요한 구역은 ESP32를 쓴다 |
| `DHT` | D7 | 13 | 외부 10kΩ 풀업 필요 |
| 여유 | D0 | 16 | 인터럽트/풀업 없음 (deep sleep 기상 전용) |

**금지 핀**: `D3(0)·D4(2)·D8(15)` — 부팅 스트랩 핀. 릴레이 IN으로 쓰면 부팅 실패하거나 부팅 중 오출력한다.

> **zone2 노드는 마이그레이션 필요.** 현행 배선은 `DHT=GPIO4`, `RELAY1=GPIO5`로 **I2C 두 핀을 점유하고 있다.**
> I2C를 쓰려면 DHT를 D7(13), 릴레이를 D5(14)로 옮기고 재플래싱해야 한다.
> **핀을 먼저 물리적으로 옮기고 나서 플래싱한다** (릴레이가 무정의 상태로 남지 않도록).

**두 칩 공통 주의**
- 아날로그는 ESP32의 경우 **ADC1에서만** 읽는다. ADC2 핀의 `analogRead()`는 WiFi 연결 상태에서 값이 나오지 않거나 쓰레기값이 나온다.
- ADC 채널이 모자라면 **ADS1115**를 I2C로 붙인다. 1개당 4채널, ADDR 핀으로 주소 4개(0x48~0x4B) → 최대 16채널.
  16비트라 두 칩의 내장 ADC보다 토양수분 캘리브레이션도 안정적이고, **칩이 달라도 raw 스케일이 같아진다**(캘리브레이션 값 공유 가능).
- **미배선 ADC 핀은 반드시 `SOIL_SENSOR_ENABLED 0`으로 두거나 10kΩ 풀다운을 단다.** 띄워두지 않는다.
- 두 칩 모두 GPIO는 **3.3V**다. 5V 릴레이 모듈은 광절연(옵토커플러) 타입을 쓰고, 3.3V 신호로 확실히 트리거되는지 확인한다.
- ESP8266 `A0`는 NodeMCU 보드의 분압 저항 덕에 0~3.3V다. 맨 ESP-12 모듈은 0~1.0V이므로 센서를 직결하면 안 된다.

## 4. 배선 규약

**색상 (예외 없이 고정)**

| 색 | 용도 |
|---|---|
| 빨강 | +12V / +5V |
| 주황 | +3.3V |
| 검정 | GND |
| 노랑 | 디지털 신호 (`RELAY*`, `DHT`) |
| 초록 | `SCL` |
| 파랑 | `SDA` |
| 흰색 | 아날로그 (`AIN*`) |

**라벨 형식**: `Z<구역>-<신호>` (예: `Z1-RELAY1`, `Z2-AIN1`). 케이블 **양 끝에 같은 라벨**을 붙인다.
칩 이름은 라벨에 넣지 않는다 — 노드를 교체해도 라벨이 그대로 유효해야 한다.

**물리 규칙**

- 브레드보드 내부 배선은 듀폰 점퍼가 아니라 **22AWG 단선(solid core)** 을 필요한 길이로 잘라 **보드에 눕혀서** 꽂는다.
  공중 아치가 사라지고, 어느 선이 어디로 가는지 눈으로 추적할 수 있게 된다.
- 모듈 간 연결은 **JST-XH 커넥터**로 만든다. 센서 추가/제거가 "뽑고 꽂기"가 되어야 한다.
- 3가닥 이상 같은 방향으로 가면 스파이럴 튜브나 벨크로 타이로 묶는다.
- 모든 모듈은 베이스 플레이트(아크릴/MDF/페그보드)에 **M3 나일론 스탠드오프로 고정**한다.
  굴러다니는 모듈이 꼬임의 근원이다.
- 릴레이 모듈은 JD-VCC 점퍼를 분리해 코일 전원을 노드와 분리한다(광절연 유지).
- 노드 개발보드의 3.3V 레귤레이터는 여유가 크지 않다(ESP8266은 더 작다). 3.3V로 액추에이터를 먹이지 않는다.

## 5. 부품 (예상 5~7만원, 국내 조달)

| 항목 | 용도 | 대략 |
|---|---|---|
| 아크릴/MDF 베이스 플레이트 + M3 스탠드오프 세트 | 모듈 고정 | 1만 |
| JST-XH 커넥터 키트 + 압착기 | P1~P4 제작 | 2만 |
| 만능기판(소형) — 노드 수만큼 | 칩별 캐리어 제작 | 3천 |
| 22AWG 단선 브레드보드 점퍼 키트(프리컷) | 보드 내부 배선 | 1만 |
| 나사 단자대(터미널 블록) 2P/3P 세트 | 전원 분배, GND 합류 | 5천 |
| ADS1115 | 아날로그 채널 확장 (ESP8266은 사실상 필수) | 5천 |
| BME280 또는 SHT31 | I2C 온습도 (DHT22 대체 → `DHT` 핀 회수) | 5천 |
| BH1750 | I2C 조도 | 3천 |
| I2C 허브 보드 (또는 만능기판 자작) | 데이지체인 | 5천 |
| 스파이럴 튜브 / 벨크로 타이 | 다발 묶음 | 5천 |

이미 조달 목록(`configs/smartfarm/procurement_items_v1.json`)에 있는 `sensor_mounting_case`와 함께 발주하면 된다.

### 국내 부품몰 검색어 (영어 명칭으로는 안 나온다)

| 찾는 것 | 국내 검색어 |
|---|---|
| 스탠드오프 | **서포트** (M3 = **3파이**). 나사는 "PCB 서포트용 볼트"로 따로 판다 |
| 암헤더 / female header | **핀헤더소켓** ("핀헤더"는 수컷이다) |
| 전원 분배용 단자대 | **중계용 단자대** 또는 **조립식 단자대**. "2P/3P"로 찾으면 기판 납땜용이 나온다 |
| 단자대 분배 액세서리 | **쇼트바** (JOTN 15A용은 `JOST-1512`) |
| 압착용 전선 | **UL1007 22AWG 연선** (점퍼와이어 키트의 단선은 압착에 부적합) |

베이스 플레이트는 부품몰의 "아크릴판"이 기판 보호용 소형(51×51mm 급)이라 쓸 수 없다.
**A4(210×297mm)가 목표 치수와 사실상 같으므로** A4 MDF 6mm를 쓴다 — 아크릴은 서포트 구멍을 뚫다가 크랙이 간다.

**중기(선택)**: 배치가 확정되면 캐리어를 커스텀 PCB로 뜬다(5장 ~2만원, 2주).
ESP32용·ESP8266용 두 종을 같은 커넥터 배치로 만들면 완전한 호환이 된다. 브레드보드는 최종 배치가 아니다.

## 6. 오늘 당장 (0원, 30분)

부품이 오기 전에도 할 수 있는 것:

1. 전원을 내리고 **모든 선을 뽑는다**.
2. 모듈을 배치 순서대로 놓는다: 좌측 = 전원/릴레이(고전압), 우측 = 센서(저전압), 중앙 = 노드.
   **전원 계통과 신호 계통이 교차하지 않게** 한다.
3. 색 규약(4장)에 맞춰 다시 꽂는다. 색이 없으면 있는 색으로 규약을 정하고 이 문서를 고친다.
4. 선 길이를 맞춘다. 20cm 점퍼로 5cm 거리를 잇지 않는다.
5. 완성 후 **사진을 찍어 이 폴더에 남긴다** (`bench_<zone>_<chip>_YYYYMMDD.jpg`). 다음에 뭘 바꿨는지 비교할 기준이 생긴다.

## 7. 배선 후 검증 절차 (전원 인가 전 필수)

1. 멀티미터 저항 모드로 **5V–GND, 3.3V–GND 단락 확인** (수십 Ω 이하면 단락 — 전원 넣지 말 것).
2. 각 신호선 양 끝 **도통 확인** (라벨이 맞는지 실측).
3. 릴레이/펌프를 분리한 채 노드만 전원 인가 → 부팅 로그(115200 baud) 확인.
4. 센서를 **한 번에 하나씩** 추가하고 매번 I2C 스캔으로 주소를 확인한다. 주소가 겹치면(ADS1115 등) ADDR 핀으로 분리한다.
   펌웨어 2.1부터 스캐너가 내장돼 있어 별도 스케치를 올릴 필요가 없다 — 부팅 시 자동 스캔해
   시리얼(115200)에 찍고, 결과를 `device/status`의 `i2c` 배열로도 발행한다. 즉 **시리얼 케이블 없이
   MQTT만으로 원격 확인이 가능하다.** 재부팅 없이 다시 스캔하려면 `diagnostic/request`를 보내면
   `diagnostic/result`의 `i2c_scan`에 최신 결과가 담겨 온다.

   ```bash
   mosquitto_sub -h <파이IP> -t 'farm/+/device/status' -v -W 40   # i2c 배열 확인
   ```

   | 센서 | 기본 주소 |
   |---|---|
   | BME280 | `0x76` 또는 `0x77` (펌웨어가 둘 다 시도) |
   | BH1750 | `0x23` (ADDR 핀 HIGH면 `0x5C`) |
   | ADS1115 | `0x48`~`0x4B` (ADDR 핀 연결에 따라) |

   스캔에 아무것도 안 잡히면 순서대로 의심한다: ① 센서 전원(3.3V) ② SDA/SCL 뒤바뀜 ③ GND 미공유 ④ 커넥터 접촉.
5. `mosquitto_sub -h <파이IP> -t 'farm/#' -v` 로 값이 올라오는지 확인.
   펌웨어 2.0(`smartfarm-node-2.0`)은 `farm/<zone>/device/status`에 노드 상태를 JSON으로 발행하므로
   30초 주기의 센서값을 기다리지 않고도 판정된다 — `board`(칩 종류), `ip`, `rssi_dbm`, `uptime_s`,
   `boot_id`(재부팅 감지), `watchdog_max_run_ms`(노드측 펌프 상한), `sensor_capabilities`,
   `actuator_capabilities`가 들어 있다. 허브도 `farm/system/pi-hub/status`에 `db_ok`/`config_ok`/`zones`를 낸다.
   **허브 생존 여부는 이 토픽부터 본다** — 2026-07-25에 이걸 모르고 journalctl과 SQLite를 한참 뒤졌다.
6. 마지막에 릴레이를 연결한다. 펌프는 **물 없이 공회전 금지** — 튜브를 물통에 담근 상태에서만 켠다.
7. 배선을 바꿨으면 `config.h`, 이 문서, 사진 세 가지를 함께 갱신한다.

### 릴레이 동작 확인은 육안으로 하지 않는다

`water_duration_s`는 3초, `cooldown_s`는 300초다. **5분에 3초 붙으므로 육안 관측 확률이 1%다.**
"릴레이가 안 붙는다"는 판단은 거의 항상 관측 실패이지 고장이 아니다 (2026-07-25 zone1에서 실제로 한 시간을 소모했다).

검증할 때는 허브의 자동 판단을 기다리지 말고 수동으로 명령을 쏜다. 노드는 `PUMP_MAX_RUN_MS`(기본 15초)까지 켜져 있으므로 충분히 관찰된다.

```bash
# 펌프를 분리하거나 튜브를 물통에 담근 뒤에 실행할 것 — 실제로 급수된다
mosquitto_pub -h <파이IP> -t 'farm/zone1/pump/cmd' -m on
mosquitto_pub -h <파이IP> -t 'farm/zone1/pump/cmd' -m off
```

동시에 `mosquitto_sub -h <파이IP> -t 'farm/zone1/#' -v`를 띄워두면 판정이 갈린다.
`pump/status`가 `on`인데 릴레이가 안 붙으면 **펌웨어는 GPIO를 HIGH로 만들었다는 뜻**이므로 배선 문제로 확정된다
(`setPump()`는 릴레이 실동작과 무관하게 status를 발행한다 — status는 명령 기록이지 동작 증거가 아니다).

### 릴레이 모듈 계열 구분

| 실크스크린 | 구조 | 트리거 | 비고 |
|---|---|---|---|
| `S` / `+` / `−` | NPN 직접 구동, 광절연 없음 | 대개 **active-HIGH** | JD-VCC 점퍼가 없다. 3.3V로 구동된다 |
| `IN1`/`IN2` + `JD-VCC` 점퍼 | 옵토커플러 | 대개 **active-LOW** | 점퍼를 분리해 코일 전원을 노드와 분리한다 |

`soil_node.ino`의 `setPump()`는 **active-HIGH 고정**이다(`digitalWrite(pin, on ? HIGH : LOW)`).
active-LOW 모듈을 쓰려면 펌웨어를 고쳐야 하므로, 모듈을 살 때 이 표를 먼저 확인한다.

모듈 자체를 판정하려면 S(또는 IN) 선을 노드에서 빼고 3.3V와 GND에 각각 직접 대본다.
어느 쪽에서 딸깍하는지가 곧 트리거 극성이고, 붙는다는 것 자체가 모듈·GND 공유·구동 전압이 모두 정상이라는 증거다.

## 8. I2C 센서를 펌웨어에서 켜기

`soil_node.ino`(펌웨어 2.1)는 I2C 센서를 지원하지만 **기본값이 전부 꺼짐**이다.
`config.h`에 매크로를 넣지 않으면 기존 노드와 동작이 같다. 배선을 마친 뒤에만 켠다.

| 매크로 | 효과 | 발행 토픽 |
|---|---|---|
| `BME280_ENABLED 1` | DHT22 대체 온습도 | 기존 `farm/<zone>/temp`·`humidity` |
| `BH1750_ENABLED 1` | 조도 | `farm/<zone>/telemetry/light_lux` |
| `ADS1115_ENABLED 1` | 아날로그 채널 확장 | — (소스로만 사용) |
| `SOIL_SOURCE_ADS1115 1` | 토양수분을 ADS1115에서 읽음 | 기존 `farm/<zone>/soil`·`soil_raw` |

설계 원칙은 **급수 판단에 쓰이는 값은 토픽을 바꾸지 않는다**는 것이다. 파이 허브는
`soil`/`soil_raw`/`temp`/`humidity`만 구독하므로, 센서를 BME280이나 ADS1115로 바꿔도
허브 코드는 손댈 필요가 없다. 조도처럼 급수와 무관한 새 지표만 `telemetry/` 경로로 보낸다
(대시보드가 `farm/+/telemetry/+`를 이미 구독한다).

**주의 세 가지**

1. **`BME280_ENABLED 1`을 켜면 `DHT_ENABLED 0`이 필수다.** 둘 다 켜면 같은 `temp` 토픽에 두 값이
   번갈아 발행되어 원인 불명의 튀는 값이 된다. 런타임에 조용히 어긋나지 않도록 **컴파일 단계에서 `#error`로 막는다.**
2. **ADS1115로 토양수분을 옮기면 캘리브레이션을 전부 다시 실측해야 한다.** raw 스케일이
   0~1023(ESP8266) 또는 0~4095(ESP32)에서 **0~32767**로 바뀐다. `SOIL_DRY_RAW`/`SOIL_WET_RAW`는 물론
   허브 `config.yaml`의 `soil_raw_min`/`soil_raw_max`까지 고치지 않으면, 허브가 정상 센서를
   범위 이탈로 보고 급수를 영구 보류한다.
3. **ESP8266은 센서 3종을 다 켜면 IRAM 93%다**(실측). 여기서 코드를 더 얹으면
   `section .text will not fit in region iram1_0_seg`로 링크가 실패한다. 여유가 필요하면 ESP32 노드로 분산한다.

켠 센서는 부팅 시 실제로 응답해야 `device/status`의 `sensor_capabilities`에 올라간다.
`config.h`에서 켰다는 사실이 아니라 **응답했다는 사실**을 신고하므로, 이 필드가 배선 상태를 그대로 보여준다.

## 9. 구역/칩별 설정 파일 관리

두 칩을 섞어 쓰면 "이 노드에 뭐가 플래싱돼 있는지"를 파일로 재현할 수 있어야 한다.
`config.h`는 항상 **직전에 빌드한 것 하나**만 남으므로, 구역별 실설정을 반드시 따로 보관한다 (README 5장).

```
config.zone1.esp32.h      # 실설정 보관 (.gitignore 대상)
config.zone2.esp8266.h
config.h                  # 빌드 직전 위 파일 중 하나를 복사
```

빌드 직전 `cp config.zone1.esp32.h config.h` 후 컴파일·업로드한다.
**보관 파일이 없는 노드는 재현 불가능한 노드다** — 지금 벤치의 ESP32가 그 상태이므로 `config.zone1.esp32.h`부터 만들어 둔다.

## 10. 하지 말 것

- 브레드보드로 펌프 전류를 흘리지 않는다.
- 노드의 5V/3.3V 출력에서 릴레이 코일이나 펌프를 먹이지 않는다 (브라운아웃 → 리부팅 → 릴레이 상태 튐).
- **스트래핑 핀에 릴레이 IN을 연결하지 않는다**: ESP32 `GPIO0·2·12·15`(특히 12는 부팅 실패)와 `5·14`, ESP8266 `D3·D4·D8`.
- ESP32 ADC2 핀(GPIO 0·2·4·12~15·25~27)에서 아날로그를 읽지 않는다 (WiFi 사용 중 동작 안 함).
- ESP8266에 아날로그 센서를 2개 이상 직결하려 하지 않는다 (A0 하나뿐 — ADS1115를 쓴다).
- 미배선 ADC 핀을 띄워둔 채 `SOIL_SENSOR_ENABLED 1`로 두지 않는다 (README 4번 참고).
- **토양센서를 흙(또는 물컵)에 넣지 않은 채 허브의 급수 판단을 켜둔 상태로 방치하지 않는다.**
  공기 중에 놓인 센서는 raw가 건조값에 붙어 `soil ≈ 0~1%`가 되고, 허브는 이를 진짜 건조로 믿고
  `cooldown_s` 주기마다 계속 펌프를 켠다. `soil_raw_min/max` 범위 검증은 **단선은 잡지만 "흙에 안 꽂힌 센서"는 잡지 못한다**
  (값이 정상 범위 안이기 때문). 벤치 테스트 중에는 센서를 흙컵에 꽂아두거나 해당 구역을 허브 설정에서 빼둔다.
- 칩이 다르다는 이유로 라벨·색·커넥터 규약을 다르게 만들지 않는다. 규격이 갈라지는 순간 이 문서의 효용이 사라진다.
- 배선을 바꾼 뒤 `config.h`를 안 고치고 테스트하지 않는다. 이 불일치가 지금까지 나온 오판의 주 원인이다.
